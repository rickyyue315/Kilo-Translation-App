01轉換範圍

分成三層：核心功能要不要留、介面怎麼改、行動端要補什麼。

核心功能

翻譯、三步精譯、雙人模式、歷史、BYOK 全部保留。唯一改道的是語音輸入與朗讀。

  • 語音輸入：Web Speech → 後端 ASR
  • 語音對話：本來就走後端，不動
  • 朗讀：speechSynthesis → 原生 TTS
  • 翻譯管線與提示詞：完全不動

介面調整

從「桌面單頁長滾動」改成「手機兩分頁 + 底部主動作」。

  • 2 分頁：翻譯／歷史，置於 header 下方
  • 錄音 orb 底部常駐 80dp
  • 設定與模型收進 Bottom Sheet
  • 卡片降噪：一屏最多 2 個帶陰影容器
  • 錄音態四重信號：形狀 → 紅環 → 文字 → 狀態點
  • 移除 hover、快捷鍵、skip-link

行動最佳化

處理只有真機才存在的問題，不是縮小版桌面。

  • Edge-to-edge 與安全區不疊加
  • 系統字級 200% 真實生效
  • 觸控命中 48dp、相鄰間隙 8dp
  • 來電／耳機／背景中斷處理
  • 離線三層提示、電量與脈動降頻

為什麼是 Capacitor，而不是 TWA 或重寫

維度Capacitor 8TWA / BubblewrapRN / Flutter 重寫
前端改動低（5 檔約 300 行）近零極高（8–12 人週）

主要風險WebView 無 Web Speech無 Chrome 即不可用排期與回歸成本

TWA 明明支援語音辨識，為什麼不用？ TWA 跑在 Chrome 裡，webkitSpeechRecognition 確實可用，但那是 Chrome 的雲端服務：音訊上傳 Google；裝置沒有 Chrome（華為、部分 AOSP、部分中國 ROM）時整個 App 直接不可用，退化為帶網址列的 Custom Tab，端點不可達時只有 onerror: network，沒有替代路徑。此外 TWA 拿不到系統欄顏色、safe-area inset、haptics、原生 TTS 與返回鍵語意。代價是「功能有沒有」，不只是「好不好看」。

語音層重構：一條主路徑，兩條增強，永不硬阻擋

1
native（Capacitor）
一律走 MediaRecorder → /api/transcribe → 翻譯。放棄即時逐字，換取跨裝置一致與音訊不出境至 Google。
2
web + Web Speech 可用
保留即時逐字；遇到 not-allowed 或 network 錯誤時降級到後端 ASR，而不是報錯收工。
3
全不可用
進入 textOnly：停用麥克風，但文字翻譯、歷史、朗讀照常。禁止像現行 checkBrowserSupport() 一樣直接阻斷整個 App。

現行 utils.js:33 checkBrowserSupport() 在 WebView 會 100% 觸發並中斷初始化。 它偵測不到 SpeechRecognition 就 showError() 並 return false。這是 Android 化的第一個阻擋點，必須改寫成「能力分級」而不是「硬阻擋」。

朗讀：必須換成原生 TTS

Android WebView 的 speechSynthesis 實務上不可用——可能為 undefined，或 getVoices() 永遠回空陣列、voiceschanged 永不觸發。現有 speech.js:525-531 的 fallback 會永久掛住，朗讀按鈕卡在 disabled，使用者只會覺得「按了沒反應」。

改用 @capacitor-community/text-to-speech@8，Web 端保留原有 speechSynthesis，由 tts.js 適配層分流。

03平台相容性考量

WebView 不是 Chrome。這一節列的是「桌面測不出來、真機才會出事」的項目。

能力Android WebViewChrome / TWA影響與對策

speechSynthesis不可靠可用原生 TTS 插件

Service Worker支援支援原生不註冊，並主動反註冊

三個會默默出事的細節

字級「假通過」

WebView 不追蹤系統字級：getComputedStyle(html).fontSize 永遠 16px。不處理的話，測試機看起來正常，低視力使用者永遠拿到小字。

對策：原生回傳 fontScale（clamp 0.85–2.0），首屏 paint 前設 root font-size；並顯式鎖 textZoom = 100，否則特定 ROM 會讓 root × textZoom 疊乘成 400%。

安全區疊加

--sab 吃到值後，若 body 再加一次 padding、dock 又自己加一次，就會出現雙倍空白帶。

對策：:root 改雙層 fallback（先取 --safe-area-inset-*，再退 env()）；header 吃 --sat；刪 body padding-bottom；dock 只在底部加一次。

白屏連鎖

三條路徑都會白屏：刪掉 #swapUsers 節點（ui.js:303 綁事件 TypeError）、舊 WebView 解析 ES module 失敗、SW 供應舊版 HTML。

對策：節點保留、inline 隱藏；platform-check.js（ES5、非 module）前置檢查；原生反註冊 SW。

API 位址與 CORS（第二個上架阻塞項）

打包後頁面 origin 是 https://localhost，fetch('/api/translate') 會打到 WebView 自己，回 404。所有端點必須經過單一出口：

// src/js/api.js
const base = (import.meta.env.VITE_API_BASE_URL || '').replace(/\/+$/, '');
export const apiUrl = (p) => `${base}${p}`;

// translation.js:296
['/api/translate', '/.netlify/functions/translate'].map(apiUrl)

採建置期環境變數而非執行期 config：dist 是打包資產，改 config 一樣要重建，換不到 OTA 彈性；建置期還能讓 CI 斷言非空，避免上架版打到 dev 後端。

BYOK 會帶 X-OpenRouter-Key，觸發 preflight，後端沒有列 allowedHeaders 就直接被擋。

app.use(cors({
  origin: (process.env.CORS_ORIGIN || '').split(',').filter(Boolean),
  methods: ['GET', 'POST', 'OPTIONS'],
  allowedHeaders: ['Content-Type', 'X-OpenRouter-Key'],
  maxAge: 86400,
}));

05打包與發佈

從零到 AAB 的完整序列，每步都附驗證點。

1
工具鏈檢查
node -v（22.x）、java -version（21）、echo $ANDROID_HOME、npx cap doctor — 全部無 error 才往下。
2
建置 Web 資產
npm ci && npm test && npm run build — 驗證 dist/ 存在且含 assets/。
3
加入平台與同步
npx cap add android（僅首次）→ npx cap sync android — 看到 Copied web assets 與插件列表才算成功。
4
Debug 建置
cd android && ./gradlew assembleDebug → adb install -r ... — 冷啟 <3s、無白屏、翻譯可用。
5
簽署金鑰（只做一次）
keytool -genkey -v -keystore kilo-release.keystore -alias kilo -keyalg RSA -keysize 2048 -validity 10000 — keystore 遺失即無法更新，備份到密碼管理器。
6
Release AAB
./gradlew clean bundleRelease — 產物 app/build/outputs/bundle/release/app-release.aab；用 bundletool 先在本機安裝驗證。
7
商店灰度
內部測試軌（≥20 人 × 48h）→ 預先發布報告 → 5% → 20% → 100%。

版本號與 CI

versionName 取自 package.json；versionCode = major×10000 + minor×100 + patch（3.0.0 → 30000），CI 追加 run number 保證唯一。

- uses: actions/setup-node@v4
  with: { node-version: 22, cache: npm }
- uses: actions/setup-java@v4
  with: { distribution: temurin, java-version: 21 }
- run: npm ci && npm test && npm run lint
- run: npm run build && npx cap sync android
- run: cd android && ./gradlew bundleRelease
- uses: actions/upload-artifact@v4
  with: { name: aab, path: android/app/build/outputs/bundle/release/app-release.aab }

npm test 與 lint 是 gate：失敗不產 AAB。keystore 由 secret 解到 $RUNNER_TEMP，build 後立即刪除。

五類「假通過」

假通過的樣子正確驗法
量到 CSS 寫 13px 就認定字級正確量 root 實際 font-size；WebView 不吃 fontScale 時永遠 16px
只查 animation-duration: 0.01ms 就認定動畫已關查 computed animation-name === 'none'
只查 id 存在就認定節點正常查 querySelectorAll 長度 = 1；重複 id 的第二個永遠是死節點
只讀 CSS 確認有 border 就認定環存在截圖看四邊；overflow: hidden 會把它裁掉
只比「閒置 vs 錄音」兩態同時比「元件 vs 所在容器」；深色下深盤對頁底只有 1.02:1

驗收清單（節錄，完整 34 條見文件）

  • 對比：兩主題 WCAG AA 失敗數 = 0（orb 白 icon on #DC2626 = 4.83、A 鈕 8.6、B 鈕 6.4）。
  • 字級真實生效：系統 200% 時 root font-size ≈32px，且 orb／命中盒／邊距數值不變（證明幾何未用 rem）。
  • 觸控：命中矩形 ≥48×48dp，例外 = 0；相鄰間隙 ≥8dp；tabs 只垂直擴張。
  • Edge-to-edge：gesture / 3-button × 淺深 4 張截圖；orb 圓底距實體底 ≥56dp。
  • 首屏：360×640 與 360×800，非內容區 ≤240dp、譯文卡 ≥200dp；切分頁 tabs 位移 0px。
  • 錄音態可辨（阻塞）：深色主題、關閉動畫時仍能分辨錄音與否（環 + 文字成立），填色亮度差 ≥1.5:1。
  • 雙人模式：收音圓有環、非收音圓無環且去彩度；名稱與語言不省略。
  • 無鬼按鈕：pill 遮擋區以 hit-test 掃描，可點元素 = 0。
  • 形狀與語意同源：圖示形狀、aria-pressed、aria-label 由同一狀態源驅動——畫面是停止方塊而 TalkBack 唸「開始錄音」即判失敗。
  • 錄音盤 vs 容器：深色下淺盤對 dock #16233D 9.4:1；兩態亮度差 light 3.87:1、dark 2.55:1。
  • 雙人 dark 不消失：idle 填色對 dock 僅 1.04–1.11:1，屬「由線到面」的刻意設計，識別由 2dp 角色色邊界承擔（#60A5FA 6.2:1／#A78BFA 5.4:1）；active 用 #60A5FA／#A78BFA，不可用 #2563EB／#7C3AED。

驗證的關鍵不是「跑過測試」，而是「在正確的環境跑」。本專案 4 個問題（Web Speech、fontScale、safe-area、color-mix）在 Chrome 桌機全部測不出來，必須用 WebView 真機或模擬器才看得到。

離線後的能力落差

不能做的

三步精譯（4B 反思品質不足、2K 放不下三段）、即時語音對話（延遲 3 秒以上破壞節奏）、多目標語言同時輸出。

能做的

文字輸入的單次翻譯、離線語音辨識（sherpa-onnx 每語言 30–80MB）、裝置端 TTS 朗讀、歷史與設定。

必須做的

「離線 · 4B」徽章、品質說明、一鍵切回雲端、模型管理頁（下載／續傳／刪除／版本）。
